True or False

1. Because Java is case-sensitive, a variable named studentAge is treated as identical to StudentAge.
False. Java distinguishes between uppercase and lowercase letters. studentAge and StudentAge are two different identifiers.
2. In Java, String literals must be enclosed in double quotes, while primitive characters use single quotes.
True. Example: "Hello" vs 'A'.
3. Polymorphism allows a method to have multiple forms, which is often implemented using the @Override annotation.
True. A child class can override a parent's method to provide its own specific behavior.
4. According to Java naming conventions, a constant variable should be written in camelCase.
False. Constants should be written in UPPER_CASE with underscores (e.g., MAX_VALUE). camelCase is used for standard variables and methods.
5. Event-Driven Programming is a paradigm where the flow of the program is determined by user actions, such as mouse clicks or keyboard inputs.
True.
6. A Class is an instance of an Object.
False. It is the other way around: An Object is an instance of a Class. The Class is the blueprint.
7. Every single line of code in a Java program must end with a semicolon.
False. Only statements end with semicolons. Class declarations, method signatures, and block definitions (which use curly braces {}) do not end with a semicolon.

Challenge 2: OOP Implementation (Encapsulation)
Write a short Java class named BankAccount.
  • It must have a private attribute called balance (double).
  • Implement Encapsulation by providing a public method deposit(double amount) to add to the balance.
  • Provide a public getter method getBalance() to return the current balance.
Solution: 
public class BankAccount {
    // Private attribute prevents unauthorized direct modification
    private double balance;

    // Public setter/modifier
    public void deposit(double amount) {
        if(amount > 0) {
            balance = balance + amount;
        }
    }

    // Public getter
    public double getBalance() {
        return balance;
    }
}
Challenge 3: Paradigm Logic
If you are writing an application where you declare what output you want (e.g., querying a database for "all active users") without writing the exact loops and steps of how the computer should fetch them, which programming paradigm are you utilizing?
Declarative Programming. Unlike procedural programming (which details the exact steps of how to do it), declarative programming focuses on what the desired result should be.
